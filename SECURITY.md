# Privacy and security reports

Never attach real media, filenames, paths, raw FFmpeg output, private state, mappings, settings, keys or screenshots of an operator session to a public issue.

Reproduce problems using generated media wherever possible. Include the application version, OS/architecture, fixed error category and reproduction steps. A sanitized diagnostic export may still be sensitive: review it locally and obtain the owner's authorization before sharing. Repository examples must be entirely synthetic.

Sensitive treatment hides queue filenames and suppresses automatic diagnostic exports and event logs. It is not encryption or an OS sandbox. Read `docs/settings-and-privacy.md` and `docs/privacy-and-diagnostics.md` for the precise boundaries.

Arrange a private reporting channel with the maintainer before transmitting vulnerability details. Use GitHub private vulnerability reporting if enabled for the public repository; otherwise request a channel without posting the exploit or confidential details publicly. No security contact email is published. Public software downloads are checksum-pinned; never disable integrity checks to bypass an installation failure.
